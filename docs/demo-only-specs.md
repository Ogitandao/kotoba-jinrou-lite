## 2. まっさら体験モード（?fresh=1・2026-11-26 追加）

新規登録直後の状態を再現するデモモード。URL に `?fresh=1` を付けるか、
設定の「まっさらな状態を見る（デモ用）」から入る（設定に「通常のデモに戻る」行もあり）。

- 中身：フレンド0・申請0・DMはようこそDMのみ・グループなし・ルーム0件・
  コイン100（登録ボーナス）・人気度0・もらったギフトなし・名前未決定
  （ログイン後にセットアップが出る）・チュートリアル未同意（フレンドタブはロック）
- 実装は Sim 内の FRESH フラグでシードを上書きするだけ。通常デモの
  localStorage 保存（同意・スターター日数）は汚さないよう書き込みをガード済み
- 検証：scripts/verify-fresh.mjs（9件）

## 3. Sim 時のみ切り替わる挙動

- **ログイン画面**：未ログイン時に表示。デモ導線（ボタンタップ→「ログイン中…」→
  フェードアウトで入る）は、Supabase 設定が無い／セッション判定ができない
  Sim 環境だけのもの。設定あり＋未ログインが確定した本番環境では Google
  ボタンが実 OAuth・Apple ボタンが「準備中」トーストに切り替わり、
  セッションがある場合は画面自体を出さない（2026-11-26 追補37／認証配線は追補55）
- **ログアウト**：Sim 時はログイン画面に戻る。本番は実 signOut＋再読み込み
  （追補55で配線済み）
- **名前セットアップの順序保証**：ログイン画面表示中は名前セットアップを
  保留し、ログイン完了後に出す（追補38）
- **デモをリセット（設定行）**：端末に残る記録（kl_starter_days／
  kl_rules_agreed）だけがデモの「続き」なので、確認ポップアップを挟んで
  その2件を消して再読み込みする。それ以外は元々リロードで初期化される

## 4. Sim 専用フック（data-adapter）

- `__simAdvanceTime(sec)`：Sim の仮想時計を進める（検証・デモ用）
- `__simApplyMyPenalty()`：ペナルティ適用テストの実体
- `__simInjectAppealablePenalty()`：異議申し立てテストの実体
- `__simResultRoomDemo()`：操作中メンバーの待機室デモの実体

いずれも Facade 側で「アクティブなバックエンドに無ければ no-op に落とす」
形になっており、Supabase バックエンドでは何も起きない。

## 5. デモ環境そのものの性質（仕様ではなく前提）

- ダミーユーザー／ルーム／DM／グループは全てシード。状態はリロードでリセット
  （例外：localStorage の `kl_starter_days` と `kl_rules_agreed` だけ残る）
- オンライン表示はシードの固定フラグ（本番の Presence は未配線）
- スターターボーナスはデモではリロードで連続受取できてしまう
  （本番は JST の日付で判定し同日2回目は不可。実DB検証済み）
- 起動時に再生される王冠ギフトの到着通知はシード DM（dm-6）によるもの
