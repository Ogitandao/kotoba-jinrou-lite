## 1. そのまま持っていけるもの

### 1-1. モデレーション／執行システム一式
正本：`docs/enforcement-design.md`（Lite repo）
- 通報 → 5分間隔のスイープでケース化（前後の文脈スナップショット付き）
→ OpenAI Moderation でスコアリング → 自動判定、という全自動パイプライン
- 決定済みポリシー U1–U10：通常カテゴリ初回は警告のみ／脅迫・未成年が
絡む性的表現は初回から無期限凍結／処分は直近90日で階段（警告→7日→
30日→無期限）／通報の重みで暫定非表示／通報者トラスト（誤通報対策）
- 流れ判定（同一投稿者・同一スレッド・7日で中間帯3件＝違反1件）と
DM の確定ライン緩和（0.85→0.75）まで実DBで稼働確認済み
- 本家は Apple の UGC 要件（通報・ブロック・フィルタ必須）対応が
G-C 審査前に必須のため、この設計がそのまま土台になる
- 注意：本家は画像とボイスがある。画像は Vision SafeSearch 等の追加
チェック、ボイスは通報時の証跡が残らない点が Lite との差分

### 1-2. ペナルティ設計（放置・AFK対策）
- ハートビート停止 → 2分猶予 → 離脱＋対戦強制終了
- 違反ポイント制：無発言＋未投票＝1.0（即退室）、片方欠け＝0.5、
蓄積 1.0 で退室＋ラダー適用
- ラダー：1時間→3時間→6時間→12時間→24時間。30日無違反で一段下降
（0には戻らない）。`penalty_until` 方式でロビーに残り時間を表示
- マスター放置（満室＋全員準備OK＋5分）も自動記録し、警告DM→
ペナルティ合算する仕組みまで実装済み
- 本家の公開ルーム運用（準備確認・自動解散など既決仕様）と組み合わせて
「仕様で回す＋違反は自動で裁く」の二層にできる

### 1-3. 「戻る」操作の設計原則と精査チェックリスト
Lite で Android 実機の挙動まで含めて詰めた知見：
- 端末の戻るジェスチャーは OS がブラウザ履歴を戻すため、そのままだと
アプリごと閉じる。対策は履歴に目印を1つ積む「履歴トラップ」方式：
戻るを「今開いているものを1つ閉じる」に変換する
- 積み直しは即時にやるとブラウザの戻るアニメーションと競合して
画面がカクつく。350ms 遅延させると滑らか（初回だけブラウザ側の
プレビューで一瞬ちらつくのは Web の限界。ネイティブ化で消える）
- 原則：ルーム／対戦に入ったら戻る操作は完全無反応（閉じるのは
画面内のボタンだけ）。ロビー側に「前の画面」を作らないことで、
退出後にスワイプでルームへ復帰することも構造的に起きない
- 確認系（送信・承認・通報）は「戻る＝キャンセル」で統一すると
誤操作で実行される事故が起きない
- 同意ゲート・名前セットアップは、戻るで閉じても未同意・未決定の
まま再表示される設計にすれば抜け道にならない
- 精査の観点：全画面×全ポップアップについて「戻れてよいか」を
一覧化してから実装する（Lite ではこの棚卸しで1件の緩さを発見）

### 1-4. モーダルの履歴スタック方式
- 開く＝スタックに積む、閉じる＝1つ前に戻る、の汎用モーダル基盤。
設定→ブロックリストのような二階層の往復が自然になる
- 本家の画面数が多い構成（4タブ＋二階層の詳細・設定系）でも
そのまま使える

### 1-5. 結果発表の演出設計（「見せない時間」の作り方）
- 投票→（逆転回答）→結果、の間に「結果集計中」のタリー画面を挟み、
結果は最後に一括開示する。情報の出し方をサーバー側フェーズで制御
- 逆転成功時は赤帯のカットイン、通常勝利は紙吹雪、と勝ち方で演出を
分ける。結果画面ではヘッダーのタイマーを隠す（固まった数字が
別のタイマーに見えて混乱するため）
- 本家の結果画面・MVP ギフト導線にも応用できる考え方

### 1-6. ギフト到着通知の「保留」設計
- 試合中はスライド通知を出さず保留し、結果画面（done）で解放する
- ログイン画面表示中も保留する（起動直後に通知が暴れない）
- 本家でも試合中バナーは出さない方針と一致するので、そのまま使える

### 1-7. スターターボーナス（新規定着）
- 登録 100 ＋ ログイン日数 7日で合計 500 を分割配布
（50,50,50,50,100,100,100。連続でなくてよい）
- 台帳に専用 reason を切る／CHECK 制約は語彙追加と同時に広げる
（後述 1-11 の実務知見とセット）
- ロビーにスタンプカード型の進捗表示

### 1-8. 年齢確認と課金上限
- 生年月日はログイン後の初回セットアップで自己申告（本人確認なし、
一度登録したら変更不可）。13歳未満は登録不可
- 月額上限：15歳以下 5,000円／16〜19歳 20,000円／20歳以上なし。
台帳の purchase を月次集計して判定
- 運営者表記は実名を出さない前提で設計（屋号「OGI games」運用、
iPhone は当面 PWA、App Store は法人化とセット）

### 1-9. チュートリアルと同意ゲート
- 7枚構成：ようこそ／遊び方／流れ／ウルフになったら／マナーと
ルール／困ったときは（通報の仕方）／コインとギフト
- 未同意の間は入室のたびに表示し、フレンドタブもロックする
- ようこそDMに「チュートリアルはこちら」を常設し、いつでも
見返せる導線をセットにする

### 1-10. PWA 化の実務
- manifest で縦固定（orientation: portrait）。横向き案内は
JS（screen.orientation）で出す（CSS メディアクエリはキーボードで
誤判定する）
- テーマ色・アイコンの変更はホーム画面への再追加が必要
（インストール時に焼き込まれる）
- アプリアイコン／ロゴは小サイズでの視認性を実寸で確認してから決める

### 1-11. Supabase 運用の実務知見
- RPC のエラーは `raise exception 'CODE: msg'` 規約で、クライアントが
コードで分岐する
- CHECK 制約は新しい語彙（reason・kind 等）を足す変更と同時に広げる。
後追いすると本番で 23514 を踏む（Lite で実際に踏んで対処済み）
- RLS ポリシーで自テーブルを参照すると 42P17（無限再帰）。判定は
security definer のヘルパー関数に逃がす
- pg_cron → pg_net → Edge Function の定期実行は verify_jwt の
回避設定と共有シークレット照合が要る
- SQL 適用は API 経由のスクリプトで（モバイルの SQL Editor への
長文貼り付けは途中で切れる）
- Free プランは無アクセスで自動一時停止がある。本家のプロジェクトも
放置期間に注意

### 1-12. 検証とデモ環境の型
- jsdom による UI フロー自動検証スイート群（ロビー／ソーシャル／
ゲーム／フレッシュ等、全スイート緑を維持してから同期する運用）
- 実DB検証スクリプト（検証用ユーザーを都度発行して RPC を叩く）
- デモ（sim）と実DBはアダプタのファサードで分離し、デモデータは
実DBに一切入れない。デモ専用仕様は `docs/demo-only-specs.md` に
棚卸しして「本番に出ないもの」を常に一覧化しておく
- 「まっさら体験」（?fresh=1）：新規ユーザーの初回状態を再現する
モード。コールドスタート確認の手法として本家でも作る価値がある

### 1-13. データ資産
- お題 429 組（19カテゴリ、恋愛系 15〜20% に厚め）。本家ワードウルフの
お題プールとして共有できる（正本はスプレッドシート
「ことば人狼 お題リスト batch1」）
- コイン台帳の設計（無料／課金の分離管理、無料から消費、ledger の
reason 体系）は本家の `coin-economy.md` と突き合わせ用になる

## 2. 読み替えて使えるもの（考え方だけ移す）

- **導線の滑らかさの基準**：Lite で「スムーズ」と評価されたのは、
画面遷移のアニメーション、スクロールの追従モデル（残り 60px
以内なら自動で追う＋rAF の滑らかスクロール）、モーダルの戻る
挙動、通知の保留、といった細部の積み重ね。本家でも同じ基準で
点検すると効く
- **アイコンの勝利数アンロック**：無料基本セット＋勝利数で解放
（5勝／10勝／20勝）。本家の装飾・実績設計の部品になる
- **フレンドまわりの操作集約**：カードに主要アクション（トーク／
ギフト／ブロック）を揃え、並びはオンライン→最近順。本家は
マイページ内フレンドセクション（既決）への落とし込み方が違う
だけで、部品は使える

## 3. 意図的に違う部分（本家へ混ぜない）

Lite の決定を本家の既決事項へ上書きしないための明記：

| 項目 | Lite | 本家（既決を維持） |
|---|---|---|
| DM の既読 | なし（客層配慮） | あり（揉める要素として意図的） |
| ワードウルフの単位 | 1ゲーム単位 | 3ゲーム1セット |
| 非公開ルーム | パスワード廃止・招待DMが資格 | パスワードあり（招待にPW表示＋コピー） |
| デザイン言語 | 明るいミント×水色・丸ゴシック | ダークネイビー×ゴールド |
| ボイス | なし（テキストのみ） | PTT ボイチャ必須（Agora） |
| 画面構成 | 下部2タブ（ロビー／フレンド） | 下部4タブ（ルーム／個人チャット／クラン／マイページ） |
| クラン・特殊村 | なし（民度対策で入れない） | クランあり |
| 客層 | 初心者・子供・主婦層を想定 | 本家の想定通り |

## 4. 本家ロードマップへの組み込み提案

- **G-B（無料配布検証）で使う**：1-3 戻る設計／1-4 モーダル基盤／
1-9 チュートリアル／1-10 PWA 実務／1-12 検証とデモ環境の型／
1-7 スターター
- **G-C（審査・有料化判断）で必須になる**：1-1 モデレーション一式／
1-2 ペナルティ／1-8 年齢確認と課金上限・実名を出さない運営表記
- **装飾フェーズで使う**：1-5 結果演出／1-6 通知の保留／2 の部品類
- **ワードウルフモード実装時に使う**：DB 駆動の進行管理（フェーズ・
タイマー・スイープ）、お題データ（1-13）。ただし §3 の差分
（3ゲーム制など本家決定）を先に確認すること

### Lite 側に残っている宿題（本家で作るときも同じ順序で必要）
- 異議申し立て（U8）は Lite 側で実装済み（2026-11-26：DB・RPC・アプリ内フォーム・Apps Script のコードまで。残るのはおぎのシート作成とスクリプト設置だけ）。本家で作るときはこの実装を雛形にできる
- 送信時の重度 NG ワードの即時ブロックと、ng_words の初期リスト投入
（現在リストは空。機械チェックの入口だけ実装済み）
- グループチャット／ルーム一覧の Realtime 化（現状はポーリング）
